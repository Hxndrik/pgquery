# Contributing to pgquery

Thanks for helping. Bug reports, small fixes and new database screens are all welcome.

## Getting set up

Requirements: Node 22+, Go 1.26+, and a Postgres to point at.

```bash
cd frontend && npm install
make dev          # Vite on :28000, proxy on :54280
```

For a realistic sample database, point the demo at a local Postgres you can throw away. The proxy seeds it on startup:

```bash
cd proxy && DEMO_DATABASE_URL="postgres://postgres@localhost:5432/scratch" ALLOW_PRIVATE_HOSTS=true go run .
```

Then use **Open the demo database** in the app. The seed lives in `proxy/demo/seed.sql`.

## Where things live

| Path | What |
|---|---|
| `frontend/src/components/app` | The React app (served at `/app`) |
| `frontend/src/lib/pgCatalogQueries.ts` | Catalog queries behind every screen |
| `frontend/src/lib/ddlGenerators.ts` | SQL generated by forms (always previewed before it runs) |
| `frontend/site` | The static website and guides, rendered at build time |
| `frontend/src/brand/pixels.ts` | Tuple and the pixel icons |
| `proxy` | Go server: static files, `/api/query`, `/api/schema`, `/api/test` |

## Before you open a pull request

```bash
cd frontend && npm run build    # type-checks and builds
cd proxy && go vet ./... && go test ./...
```

`go test` skips the database round-trip test unless `PGQUERY_TEST_DATABASE_URL` points at a scratch database (admin user). It loads the demo seed in a transaction that is rolled back and checks that every value in `type_edge_cases` reads and writes back unchanged; CI runs it against Postgres 18. Touching how values are read or written? Run it locally.

- Use [conventional commit](https://www.conventionalcommits.org) prefixes in commit messages and PR titles: `fix:` (patch release), `feat:` (minor release), `docs:`, `chore:`, `refactor:`, `test:`. Add `!` (e.g. `feat!:`) for breaking changes.
- Keep changes focused; one feature or fix per pull request.
- Anything that changes the database must show its SQL before it runs.
- New screens use the design tokens in `frontend/src/index.css`, not hard-coded colors.
- If you change the pixel art, run `node scripts/assets/build.ts` and commit the regenerated files.

## Releases

Releases are automated with [release-please](https://github.com/googleapis/release-please). After changes land on `main`, a bot keeps a pull request titled `chore(main): release x.y.z` open with the next version and changelog. Merging it tags the release, publishes it on GitHub and builds the `latest` and versioned Docker images.

## Good first issues

Look for the `good first issue` label. Adding a check to the Security or Performance Advisor is a nice self-contained start.
